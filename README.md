# Interview materials

Assessment materials for one engineering hire. Three rounds, all run on site.

> **This repo is interviewer-facing and private.** It contains answer keys and
> documents exactly where the seeded defects live. Candidates never clone it —
> they work on a machine you prepare, or get files you copy out.
>
> Read **[CONTEXT.md](CONTEXT.md)** first: who the hire is, why the loop is
> shaped this way, and what is still open.

## Setting up on a new machine

Needs **Python 3.11+**, `make`, and `git`. No network at interview time
— Flaskr is vendored in `app/`.

```bash
git clone <this repo> interviews
cd interviews

make setup     # builds work/round2 and work/round3, each with its own venv
make verify    # proves every seeded defect still fires and both suites are green
```

`make verify` should end with `All rounds verified.` If it doesn't, **stop** —
a defect that has stopped firing means that round silently measures nothing, and
you cannot tell from the outside.

Run `make` on its own for the full target list.

## Layout

```
app/                  flaskr, vendored from pallets/flask tag 3.1.0. PRISTINE.
                      Never edit — it is the baseline both rounds are built from.
round1_code_read/     round 1: a 25-line function we wrote, its tests, answer key
round2_build/         round 2: task, the seeded search.py, prep + verify scripts
round3_review/        round 3: the review diff, questions, answer key
scorecard/            weighted criteria and the fresher anchors
work/                 GENERATED by `make setup`. Gitignored. Safe to delete.
```

`app/` is never modified. `make setup` copies it into `work/` and applies each
round's changes there, so resetting between candidates is `make reset` and can't
go wrong.

## The rounds

| Round | Candidate gets | AI tools | Verified by |
|---|---|---|---|
| 1 — code read & fundamentals | `active_plan.py`, then its test file | **off** | `make test-round1` |
| 2 — observed build | a prepared machine + `TASK.md` | on, expected | `make verify` |
| 3 — reverse code review | the checked-out branch + `QUESTIONS.md` | on | `make verify` |

Each round's `ANSWER_KEY.md` carries verified outputs, not expectations — every
figure in them was produced by running the code.

### Round 1

```bash
make candidate-round1
```

On Windows, do not append a `#` comment to a command. `cmd.exe` passes it to
`make` as another target instead of treating it as a comment.

Hand over the test file only *after* the three questions are done.

### Round 2

```bash
make run-round2
make seed-round2
```

Register a user in the browser before running `make seed-round2` in another
shell. The seed loads 30 sample posts, including 14 matching `"apple"`.

The 14 matters — it is above the helper's `DEFAULT_LIMIT` of 10, which is what
makes one of the defects visible on screen instead of theoretical.

Prep detail and the between-candidates reset are in
[round2_build/VERIFY.md](round2_build/VERIFY.md).

### Round 3

```bash
make run-round3
```

They read `round3_review/review.diff` — 139 lines, 6 files. **The suite passes
on that branch**, deliberately.

## Preparing the candidate workstation

The candidate gets a shell on this machine in rounds 2 and 3, so they can read
anything left on disk. A private GitHub repo does not protect you here — the
clone is local. **Strip the box after building it.**

```bash
git clone <private repo url> interviews && cd interviews
make setup && make verify

make seed-round2
make candidate-round1

rm -rf app round1_code_read round2_build round3_review scorecard \
       README.md CONTEXT.md Makefile .git
```

Run the seed after registering a user, then run the candidate handoff before
removing the interviewer files. Keep `work/` in place.

Order matters — `make seed-round2` reads `round2_build/seed_dev_data.py` and
`make candidate-round1` reads `round1_code_read/`. Both are gone after the strip.

**Do not move or rename `work/`.** Each work tree holds an editable install
bound to its absolute path:

```
work/round2/.venv/.../__editable__.pth -> /path/to/interviews/work/round2
```

Move the directory and the install breaks. Delete the interviewer files *around*
`work/`, leaving it exactly where `make setup` put it.

Removing `.git` matters as much as the files: history carries every answer key,
so a clone with `.git` intact can recover all of them.

Verify the stripped tree:

```bash
grep -ril "answer\|defect\|seeded" . && echo "STILL DIRTY — do not hand over"
```

Resetting after the strip is a fresh `git clone`, not `make reset` — the
Makefile and `.git` are gone. That rebuilds from a known-good remote rather than
local state, which is the safer reset anyway.

## Between candidates

```bash
make reset && make verify
```

`make reset` throws away `work/` and rebuilds from `app/`, so a previous
candidate's edits cannot leak into the next session.

## Before handing any file over

Everything under `work/` that a candidate touches is safe. Everything else in
this repo is not. Never copy out:

- any `ANSWER_KEY.md`
- `round2_build/VERIFY.md`, `round2_build/seed/`, `round*/verify_defects.py`
- `round2_build/seed_dev_data.py`
- `CONTEXT.md`, `scorecard/`

Cheap check on a staged copy:

```bash
grep -ril "answer\|defect\|seeded" /path/to/copy && echo "DO NOT HAND OVER"
```

## Maintenance

Re-run `make verify` quarterly and re-read the answer keys. Rotate a defect if a
candidate ever turns up already knowing what's in it.
